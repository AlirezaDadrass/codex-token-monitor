# نصب توسط ایجنت

این صفحه را می‌توان همراه لینک ریپو به Codex یا هر ایجنتی که دسترسی نصب محلی دارد داد. نتیجهٔ مورد انتظار، نصب واقعی ابزار، ثبت MCP و تولید گزارش HTML است.

## متنی که به ایجنت بدهید

> این پروژه را روی همین کامپیوتر نصب کن: https://github.com/AlirezaDadrass/codex-token-monitor . راهنمای AGENTS.md و docs/AGENT_INSTALL.md را بخوان. ابتدا نام این کامپیوتر در گزارش، آدرس سرور و توکن اتصال یا مسیر فایل آن را از من بگیر. سپس نصب و اتصال را بررسی کن و با ابزار خودش گزارش HTML بساز. کلید را در خروجی یا آرگومان فرمان‌ها ننویس.

## ۱. اطلاعات لازم را بگیر

اگر این اطلاعات قبلاً در همین گفتگو داده نشده‌اند، یک‌جا از کاربر بپرس:

1. **نام این دستگاه در گزارش**، مثل «لپ‌تاپ خانه» یا «کامپیوتر دفتر»؛ نام را از روی hostname حدس نزن.
2. **آدرس مرکز مشترک**، مثل `https://monitor.example.com` یا `http://127.0.0.1:8787` در صورت تونل SSH. مسیر `/mcp` را به آدرس مرکز اضافه نکن.
3. **توکن مرکز**؛ ترجیحاً مسیر فایل توکن موجود یا یک secret محیطی. این کلید، توکن همین ابزار است؛ API key یا فایل ورود OpenAI نیست.

بدون آدرس/توکن، نصب را به حالت محلی تبدیل نکن. اگر کاربر فقط حالت محلی می‌خواهد، با انتخاب صریح او از `--local` استفاده کن. اگر هنوز سروری وجود ندارد، ابتدا مشخص کن کاربر سرور را روی کدام میزبان می‌خواهد؛ راهنمای [SERVER.md](SERVER.md) را همان‌جا اجرا کن.

توکن واقعی را بازگو نکن. آن را در command line، URL، git، فایل نمونه، shell history، screenshot یا خروجی نهایی نگذار. برای گرفتن توکن از محیطی استفاده کن که ورود secret را پشتیبانی می‌کند؛ اگر چنین امکانی نداری، از کاربر مسیر یک فایل محلی حاوی توکن را بگیر. فایل را برای فهمیدن مقدار توکن چاپ نکن.

## نصب ویندوز

روی ویندوز از [اسکریپت PowerShell آماده](WINDOWS.md) استفاده کن؛ روی سیستم مقصد Go نصب یا برنامه را کامپایل نکن. حالت پیش‌فرض Client است؛ فقط اگر کاربر همین میزبان را برای سرور انتخاب کرده، حالت Server را اجرا کن. فایل `install-windows.ps1` و ZIP هر دو در Release هستند. نام، آدرس و توکن را ابتدا از کاربر بگیر؛ توکن را با SecureString یا مسیر فایل خصوصی بده.

## ۲. فایل اجرایی را آماده کن

روی سیستم مقصد، از انتشار [v0.1.4](https://github.com/AlirezaDadrass/codex-token-monitor/releases/tag/v0.1.4) فایل مطابق سیستم و CPU را دانلود کن و SHA-256 آن را با `checksums.txt` همان انتشار بررسی کن. باینری‌ها برای Linux/macOS/Windows و amd64/arm64 منتشر می‌شوند. فایل اجرایی را در یک مسیر پایدار قرار بده؛ MCP همان مسیر را بعداً اجرا می‌کند. از پوشهٔ موقت اجرا نکن.

اگر Go 1.26 یا جدیدتر روی میزبان نصب است، از سورس بساز:

```sh
git clone https://github.com/AlirezaDadrass/codex-token-monitor.git
cd codex-token-monitor
git checkout v0.1.4
go build -trimpath -o bin/token-monitor ./cmd/token-monitor
```

در ویندوز خروجی را `bin/token-monitor.exe` بگذار. برای نصب از سورس یا باینری به Docker نیاز نیست. اگر Go در دسترس نیست، از انتشار آماده استفاده کن؛ بدون نیاز، ابزارها یا سرویس‌های سیستم را تغییر نده.

## ۳. نصب غیرتعاملیِ ایجنت

وقتی کاربر نام، آدرس و مسیر فایل توکن را داده است:

```sh
/absolute/path/token-monitor install \
  --non-interactive \
  --name "نام تأییدشدهٔ دستگاه" \
  --hub-url https://monitor.example.com \
  --token-file /absolute/path/hub-token
```

فایل توکن باید بعد از نصب هم در همان مسیر باقی بماند و فقط برای کاربر مربوط قابل خواندن باشد. مقدار کلید در آرگومان‌ها نیست. آرگومان‌ها را با API ساختاریافته یا quoting صحیح shell بساز؛ نام دستگاه ورودی کاربر است و نباید به‌عنوان کد shell تفسیر شود.

اگر توکن در `TOKEN_MONITOR_HUB_TOKEN` امنِ محیط موجود است، `--token-file` را حذف کن. نصب‌کننده مقدار را در فایل خصوصیِ کنار تنظیمات ذخیره می‌کند تا اجرای بعدی Codex هم متصل شود؛ مقدار آن را چاپ نمی‌کند.

گزینهٔ `--token-stdin` هم برای دریافت کلید از stdin موجود است. اگر ابزار اجرای تو stdin امن دارد، از آن استفاده کن. مقدار واقعی کلید را در متن فرمان یا `echo ...` نگذار. `--non-interactive` باعث می‌شود مقادیر ناقص سریعاً خطا بدهند و ایجنت منتظر ورودی ترمینال نماند.

نصب‌کننده قبل از ثبت MCP، `/health` مرکز را با توکن بررسی و سپس اولین snapshot را ارسال می‌کند؛ صرف اتصالِ موفق کافی نیست. حتی دستگاه بدون لاگ مصرف هم باید در هاب ثبت شود. اگر آدرس اشتباه، مرکز خاموش یا توکن نامعتبر باشد، نصب ناقص به‌عنوان موفق گزارش نمی‌شود. فقط وقتی کاربر آگاهانه نصب آفلاین می‌خواهد، `--skip-check` بده و بررسی اتصال و اولین ارسال را به‌عنوان کار باقی‌مانده اعلام کن.

## ۴. نصب دستی تعاملی

وقتی خود کاربر در ترمینال حضور دارد:

```sh
/absolute/path/token-monitor install
```

این فرمان سه سؤال می‌پرسد: نام دستگاه، آدرس سرور، توکن. ورود توکن در ترمینال مخفی است. کلید در فایل خصوصی ذخیره می‌شود و سپس فایل اجرایی در Codex ثبت می‌شود. اجرای دوبارهٔ نصب، نام و شناسهٔ قبلی را نگه می‌دارد؛ برای تغییر تنظیمات، همان پروفایل را ویرایش کن.

## ۵. بررسی نتیجه

نصب‌کننده از `codex mcp add` استفاده می‌کند. اگر Codex CLI موجود نیست، تنظیمات [codex-local.toml](../examples/codex-local.toml) را با مسیرهای واقعی در تنظیمات MCP همان کلاینت ثبت کن؛ سرور با stdio اجرا می‌شود.

بعد از ثبت، معمولاً اتصال MCP باید در کلاینت تازه‌سازی شود یا چت/برنامه دوباره باز شود. خود ایجنت نمی‌تواند ابزارهای جلسهٔ جاری را تضمین‌شده از نو بارگذاری کند. تا آن زمان می‌تواند ساخت گزارش روی هاب را مستقیم درخواست کند و لینک را نشان دهد:

```sh
/absolute/path/token-monitor report --html
```

پس از بارگذاری MCP، `generate_usage_report` را یک‌بار فراخوانی کن. این ابزار فایل محلی نمی‌سازد و هنگام قطعی هاب، آمار محلی را جایگزین نمی‌کند. فقط لینک `display_markdown` را به کاربر نمایش بده؛ تولید HTML و نمودارها به مدل احتیاج ندارد و محتوای کامل فایل نباید وارد کانتکست شود.

در پایان بگو: نام ثبت‌شده، اینکه بررسی احراز هویت موفق بوده، تعداد واقعی دستگاه‌های گزارش‌دهنده و لینک گزارش. تعداد دستگاه‌ها سقف یا مقدار ازپیش‌تعیین‌شده ندارد؛ هیچ دستگاهی را صرفاً به‌دلیل نرسیدن به عدد فرضی «غایب» معرفی نکن. وضعیت پوشش فقط دربارهٔ دستگاه‌های ثبت‌شده است. سهم دستگاه از لیمیت، برآورد است؛ سهم توکن‌های مشاهده‌شده محاسبهٔ مستقیم است.

## جمع‌آوری دائمی

MCP محلی تا وقتی Codex آن را باز نگه دارد، در پس‌زمینه همگام می‌کند. اگر جمع‌آوری مستقل از Codex لازم است، `token-monitor watch` را با سرویس کاربر اجرا کن. نمونهٔ Linux در [token-monitor-watch.service](../examples/token-monitor-watch.service) است. در ویندوز، نصب‌کنندهٔ PowerShell به‌صورت پیش‌فرض task جمع‌کنندهٔ همان کاربر را می‌سازد، شروع می‌کند و هنگام ورود بعدی کاربر اجرا می‌کند؛ ارسال خودکار به بارگذاری MCP یا بازبودن چت وابسته نیست. روی macOS می‌توان launchd را در صورت نیاز تنظیم کرد. در لینوکس/macOS، ثبت MCP به‌تنهایی اجرای همیشگیِ خارج از Codex را تضمین نمی‌کند.
