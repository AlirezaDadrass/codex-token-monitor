# تنظیمات، فرمان‌ها و رفع اشکال

## مسیر تنظیمات

پیش‌فرض از `os.UserConfigDir()` سیستم گرفته می‌شود:

| سیستم | مسیر متداول |
| --- | --- |
| Linux | `~/.config/codex-token-monitor/config.json` یا مسیر `XDG_CONFIG_HOME` |
| macOS | `~/Library/Application Support/codex-token-monitor/config.json` |
| Windows | `%AppData%\codex-token-monitor\config.json` |
| سرورِ نصب‌شده با اسکریپت | `/etc/codex-token-monitor/config.json` |

با `--config` می‌توان یک پروفایل جدا ساخت. این گزینه بعد از نام فرمان می‌آید، مثلاً `token-monitor report --config /path/config.json --html`.

## فیلدهای فایل

نمونهٔ بدون secret در [config.example.json](../examples/config.example.json) است.

| فیلد | توضیح / پیش‌فرض |
| --- | --- |
| `machine_id` | شناسهٔ تصادفی پایدار نصب؛ بین کامپیوترها کپی نشود |
| `machine_name` | نام واردشدهٔ کاربر؛ در گزارش نمایش داده می‌شود |
| `account` | نام گروه مشترک؛ `personal` |
| `codex_home` | مسیر دادهٔ Codex، از `CODEX_HOME` یا `~/.codex` |
| `data_dir` | کش، snapshot و گزارش‌های همین ابزار |
| `hub_url` | آدرس پایهٔ مرکز برای کلاینت؛ بدون `/mcp` |
| `public_url` | آدرس بیرونی مرکز برای لینک گزارش، مخصوص reverse proxy |
| `token_file` | مسیر فایل خصوصی توکن؛ مقدار کلید در config قرار نمی‌گیرد |
| `interval_seconds` | فاصلهٔ جمع‌آوری، پیش‌فرض ۶۰، بازهٔ ۵ تا ۸۶۴۰۰ |
| `retention_days` | نگهداری آمار، پیش‌فرض ۱۴، بازهٔ ۸ تا ۳۶۵ |
| `limit_id` | سبد سهمیه؛ پیش‌فرض `codex` |
| `account_fingerprint` | فیلتر اختیاریِ حساب در لاگ‌های متعلق به چند حساب |

مسیرهای نسبی در فایل تنظیمات نسبت به پوشهٔ همان فایل حل می‌شوند. مسیرهای `~/...` هم پشتیبانی می‌شوند. پس از تغییر تنظیمات، MCP یا `watch` و در صورت لزوم سرویس سرور را دوباره راه‌اندازی کنید.

متغیر `TOKEN_MONITOR_HUB_TOKEN` در زمان اجرا بر فایل توکن اولویت دارد. اگر این متغیر قدیمی باشد، با وجود درست بودن فایل، احراز هویت شکست می‌خورد. کلید باید دست‌کم ۳۲ کاراکتر و بدون فاصله/خط جدید باشد. کلید تولیدی ابزار ۶۴ رقم hex برابر با ۲۵۶ بیت تصادفی است.

تعداد دستگاه‌ها تنظیم یا سقف ثابتی ندارد. هر شناسهٔ جدید به گزارش اضافه می‌شود. فیلد قدیمی `expected_machines` اگر در فایل‌های نسخهٔ قبل باقی مانده باشد، در نسخهٔ جدید نادیده گرفته می‌شود. کامل بودن داده بر اساس تازگی، سابقه و خطاهای دستگاه‌های ثبت‌شده سنجیده می‌شود و شامل دستگاه‌هایی که هیچ‌وقت متصل نشده‌اند نیست.

## فرمان‌ها

| فرمان | کاربرد |
| --- | --- |
| `install` | گرفتن نام، آدرس و توکن، بررسی اتصال و ثبت MCP در Codex |
| `install --local` | نصب صریح حالت مستقل بدون مرکز |
| `init` | فقط ایجاد تنظیمات، بدون ثبت MCP |
| `collect` | یک دور خواندن افزایشی و ارسال به مرکز |
| `watch` | جمع‌آوری و همگام‌سازی دوره‌ای |
| `report` | دادهٔ ساختاریافتهٔ گزارش |
| `report --html` | تولید فایل HTML کامل بدون فراخوانی مدل |
| `report --html --output /path/report.html` | ساخت/جایگزینی فایل خروجی انتخاب‌شده |
| `report --no-refresh` | خواندن snapshotهای ذخیره‌شده |
| `mcp` | سرور MCP محلی با stdio و جمع‌آوری پس‌زمینه |
| `hub` | مرکز احرازشدهٔ HTTP و Streamable HTTP MCP |

برای گزینه‌های هر فرمان `token-monitor COMMAND --help` را ببینید. گزینه‌های مهم نصب:

```text
--name NAME             نام نمایشی دستگاه
--hub-url URL           آدرس مرکز مشترک
--token-file PATH       فایل توکن موجود و پایدار
--token-stdin           دریافت secret از stdin
--non-interactive       خطا به‌جای سؤال برای ورودی ناقص
--skip-check            نصب آفلاین با تعویق بررسی اتصال
--local                 حالت مستقل با انتخاب صریح کاربر
--create-token          ساخت کلید جدید، برای پروفایل مرکز
--public-url URL        آدرس بیرونی لینک گزارشِ مرکز
--config PATH           مسیر پروفایل
--data-dir PATH         مسیر دادهٔ ابزار
--codex-home PATH       مسیر لاگ‌های کدکس
--account LABEL         گروه مشترک دستگاه‌ها
```

## خطاهای رایج

**نصب آدرس/توکن می‌خواهد:** نصب کلاینت به‌صورت پیش‌فرض برای مرکز مشترک است. اطلاعات را از صاحب مرکز بگیرید. نصب محلی فقط با `--local` انجام می‌شود.

**۴۰۱ یا unauthorized:** توکن کلاینت و مرکز یکسان نیست، متغیر محیطی قدیمی روی فایل اولویت دارد، یا reverse proxy هدر Authorization را حذف می‌کند. کلید را چاپ نکنید؛ مسیر/منبع آن را بررسی کنید.

**مرکز در دسترس نیست:** hostname، پورت، DNS، TLS، فایروال و تونل SSH را بررسی کنید. فایل گزارش با `local_fallback` فقط دادهٔ محلی را دارد؛ آن را گزارش کامل همهٔ دستگاه‌ها فرض نکنید.

**فقط یک دستگاه در گزارش است:** روی بقیه دستگاه‌ها `collect` یا `watch` را با همان account و مرکز اجرا کنید. افزودن MCP شبکه‌ای به‌تنهایی، لاگ محلی آن دستگاه را به مرکز نمی‌فرستد.

**تغییر نام، دستگاه جدید ایجاد کرد:** `machine_id` را حفظ کنید و فقط `machine_name` را تغییر دهید. پروفایل یک کامپیوتر را برای بقیه کپی نکنید. شناسه‌های قدیمی در snapshotهای مرکز باقی می‌مانند؛ حذف هر دستگاه باید با شناخت فایل snapshot مربوط و پشتیبان انجام شود.

**وجود چند حساب OpenAI:** ابزار حساب‌ها را بی‌صدا ترکیب نمی‌کند. fingerprint حساب مطلوب را از پیام خطا انتخاب و روی جمع‌کننده‌ها تنظیم کنید. بعد دوباره sync کنید. fingerprint یک هش است و کلید ورود نیست.

**درصد لیمیت دستگاه خالی است:** داده ناقص/قدیمی است، درصد سهمیه نامشخص است یا لیمیت به پایان رسیده؛ ابزار به‌جای ساختن عدد نامطمئن آن را خالی می‌گذارد. تعداد توکن همچنان قابل مشاهده است.

**لینک گزارش سرور ۴۰۱ می‌دهد:** امضای لینک منقضی/تغییر داده شده یا توکن مرکز عوض شده است. گزارش تازه بسازید. لینک‌ها فقط یک ساعت اعتبار دارند؛ فایل HTML دانلودشده مستقل باقی می‌ماند.

**اسکن اول کند است:** نخستین بار تمام خطوط مرتبط در لاگ‌های تازه بررسی می‌شوند؛ دفعات بعد از cursor قبلی ادامه داده می‌شود. فایل‌های Codex تغییر داده نمی‌شوند.

**Codex ابزار جدید را نمی‌بیند:** پیکربندی MCP را تازه‌سازی کنید یا برنامه/چت را دوباره باز کنید. قبل از آن، `report --html` هم کار می‌کند. اگر از کلاینت دیگری استفاده می‌کنید، فرمان stdio را دستی ثبت کنید.

## بررسی برای توسعه‌دهنده

```sh
go test -race ./...
go vet ./...
go build -trimpath -o bin/token-monitor ./cmd/token-monitor
bash -n scripts/install-server.sh scripts/build-release.sh
```

برای ساخت بسته‌های انتشار: `bash scripts/build-release.sh v0.1.1`. ساخت با ابزار بومی Go و بدون CGO انجام می‌شود. این پروژه برای توسعه/تست به سرویس پایگاه داده یا کانتینر نیاز ندارد.
